# 上手与观察清单

这份文档是为"开始真实使用"准备的。目标不只是会用，而是**让这次真实使用产出有用的证据** ——
后面的开发方向应该由真实数据决定，而不是我再造一个里程碑。

## 一、启动

**最省事的一条路：双击项目根目录的 `start.cmd`**（不用打任何参数）。

它会起本地服务、自动打开浏览器；**关掉那个黑窗口就是停掉服务**。
双击路径会让操作系统直接分配空闲端口，不再把 8787 上"随便哪个监听者"误认成这个程序；
实际地址会打印在终端里。

页面先显示启动状态并检查 `.venv`。完整就自动进聊天；不完整时可以选择：
- **下载并安装**：留空镜像走官方 PyPI，或填一个本次使用的镜像；进度条旁可暂停/继续或退出下载。
- **暂不下载**：直接进入聊天，联网、图片/OCR 等可选依赖缺失时仍会明确报错。
- 退出下载会终止 pip、删除这次下载并恢复旧环境，然后继续聊天。拒绝与退出都不写持久偏好，
  所以环境仍不完整时，下次启动还会问。

或者用命令行（参数更全）：

```bat
run.cmd --web
```

默认 `http://127.0.0.1:8787` 并自动打开浏览器。它与双击入口**同样默认先检查并引导 venv**；
环境不完整时会停在同意页，直到你明确选择。只有 `run.cmd --web --no-guided-venv` 会有意跳过这道门。

- 换端口：`run.cmd --web --port 9000`
- 不想自动开浏览器：`run.cmd --web --no-open`
- **默认只监听本机**。想给局域网里同学访问要显式 `--host 0.0.0.0`，
  但那时应当先加鉴权 —— 记忆库里是你的用户画像。

> 如果想用命令行：`run.cmd` 直接进交互对话，其它命令见 README。

## 一点五、先加一个接口（第一次必做）

**新装好的机器上一个接口都没有** —— 这不是坏了，是故意的：
本项目不预置任何 key，也没有哪家供应商是"主要的"。每个人填自己的。

第一次打开界面会自动跳到 **⚙ 设置 → 接口**（没跳的话点左下角「设置」）。然后：

1. 在最下面的下拉里挑一个预设（例如你手上是哪种 key 就选哪种）。
2. 点 **添加这个接口**。
3. 在卡片里 **API Key** 一栏粘贴**你自己的** key，点 **保存**。
4. 点 **获取模型列表** —— 它会去调该供应商的 `/models`，拿回真实在售的模型。
5. 回到顶部「新会话默认」，选一个模型。想省钱就选便宜的。

**如果你用的是 Kimi Code 订阅（我们这群人大多是这种）**：选
「Kimi Code（订阅 token plan）」—— 它就是为这个准备的。

> ⚠ 注意区分：**Kimi Code（订阅 token plan）** 与 **Kimi 开放平台（按量付费）**
> 是两条产品线、两套 key、**两种协议**。前者走 Anthropic 格式
> （`api.kimi.com/coding/v1`），后者走 OpenAI 格式（`api.moonshot.cn/v1`）。
> 选错了会直接报错。
>
> base_url 记得带 `/v1`：对话端点两种写法都行，但「获取模型列表」需要它。
> 这个端点已经实测跑通了（`kimi-for-coding` 等模型都能正常用）。

其他预设：DeepSeek / 智谱 / 通义 / 硅基流动 / OpenRouter / OpenAI。
想用**完全免费**的，选「本地 Ollama」——前提是你本机装过 Ollama 并拉过模型。

**上下文窗口只能按模型填**（卡片里那张「模型」表格的「上下文上限」一列）：
**不填就是 200k**，也可以写 `128k` 或 `1M`（**k = 1000，M = 1000k**）。
这个值决定自动 compact 在哪触发，**填错不会坏**，只会早/晚触发。

表格是一行一个模型：`模型 ID` + `上下文上限` + `显示名`（显示名只影响下拉框里怎么显示，
不填就用 id；行尾能删、下面能加）。

没有"每家一个数字"的选项，是因为同一家的模型差别太大 ——
Kimi 有 8k 也有 256k，DeepSeek 从 64k 到 1M，整家共用一个数必然是错的。
常跑的模型建议填上（如 `deepseek-v4-pro` 那一行填 `1M`）。

> 所有 key 只存在本机的 `data/providers.json`，不会上传到任何地方。
> 界面上永远只显示掩码（`sk-b3……cc6f`）；表单里留空表示"不改动"。

## 二、花 10 分钟走一遍

> 记忆 / Dream / 用量 现在都在左下角 **⚙ 设置** 里（顶部那四个标签已经撤掉，主区只留对话）。
> 对话页右上角可以直接切**模型**与 **thinking 档位**，选择跟着这个会话存下来。

每一步都写了"该看到什么"和"看到别的说明什么"。

| # | 你做什么 | 该看到什么 | 如果不对，说明什么 |
|---|---|---|---|
| 1 | 说一段真实的自我介绍（名字、工作、习惯、正在做的事） | 记忆页出现几条 id + 正文条目，内容稳定、没有闲聊噪声 | 出现"用户说你好"这类噪声 → 记忆过松；一条都没记 → 记忆过紧 |
| 2 | 问一个记忆里**没有**的细节（例如"我妹妹叫什么"） | 明确说不知道，并列出它真正记得的 | **编造了** → 防幻觉失效，这是最严重的问题 |
| 3 | 更正一条：「其实我不是…，是…」 | 用的是 `mem_edit`（记忆页里是同一条 id，内容变了） | 新建了一条 → 记忆重复堆积 |
| 4 | 在**记忆页**手工改一条内容（点"编辑"） | 下一轮对话它用的是改后的版本 | 没用上 → 注入没生效 |
| 5 | 说「忘掉关于 X 的记忆」 | 记忆页那条消失（勾"显示已删除"能看到原文） | 只口头答应没删 → 工具调用失败 |
| 6 | 点「新对话」，问刚才记过的事 | 它答得出来 | 答不出 → 跨会话记忆失效 |
| 7 | 在**记忆页**把上限改成比现有条数小（比如现在有 5 条，填 3） | 弹出"上限太低：现在已经有 5 条记忆…" | 真的改下去了 → 有记忆被静默藏起来，严重 bug |
| 8 | 把上限改成 5，再让它记第 6 件事 | 它说记不下（`mem_create` 报"记忆条数过多"），并试着用 `mem_edit` 并进已有的 | 假装记住了 / 悄悄丢掉最旧那条 → 静默失败 |
| 8 | 去 Dream 页，点**整理一次**（确认框里会再提醒一次：不可撤销、没有预演） | 档案建起来，Dream 页的改动清单、结构校验都说得清它改了什么 | 它改完之后 README 与档案对不上、或结构校验报了一堆问题 → 整理质量问题 |
| 9 | （可选）点**格式化并初始化 dream**，把确认词打进去 | 档案/运行记录/进度都清成 0，**对话与记忆一条不少**，并建好空骨架 | 对话或记忆被动了 → 严重 bug |

第 9 步是"改坏了怎么办"的演练：**没有预演、也没有回滚**，能重来的方式就是
清空 dream 层再让模型整理一遍（代价是再花一次钱，而且手写的档案不会回来）。
它**只动 dream 那三样**，所以拿它演练是安全的。

## 三、我想知道的（请回来说这些）

不用写报告，几句话就够。真正有价值的是**具体的反例**：

1. **它记了什么不该记的？** 原话 + 生成的记忆内容。
2. **它漏记了什么明显该记的？**
3. **有没有出现语义重复**（同一件事两三条）或**互相矛盾**的条目？
4. **有没有一次是编造的**？（记忆里没有却说得像有）
5. **记忆有没有用上**：问一件事，记忆里明明有，它却没用上 —— 把问题原话给我。
   记忆现在是**全量注入**的（每条都在上下文里，没有"没被检索到"这回事），
   所以这种情况通常意味着"那条记忆其实没被写下来"或"写得让它读不出来"。
   用 `run.cmd --memories` 看当前库（离线、不花钱）：条目内容、`有效 N/上限 M`、
   以及**有没有条目因为太长没进上下文**。
6. **记忆满了没有**：`mem_create` 会直接失败（"记忆条数过多"）。
   上限在 设置 → 记忆 里改（0–100，不能低于已有条数）。如果它经常撞上限，
   说明该合并了 —— 或者该把上限调高一点。
7. **dream 的判断你同意吗**：它整理出来的档案里，哪条你觉得不该那么写、
   哪份该合并却没合并、哪份该删却留着（**注意：整理没有回滚也没有预演**，
   不满意的可以先在界面上直接编辑，或者整层格式化重来）。
8. **界面哪里别扭**（按钮、布局、看不清的地方）。

第 5 条特别有用：它是我能否改进记忆质量的唯一切入点，而且复现不需要花钱。

## 四、花钱的预期

`deepseek-flash` 官方价（2026-10-05 取自官方价目表）：

| | 高峰时段（工作日 9-12、14-18） | 空闲时段（其余，含周末） |
|---|---|---|
| 输入·缓存**未命中** | 2 元 / 百万 token | 1 元 |
| 输入·缓存**命中** | 0.04 元 | **0.02 元** |
| 输出 | 8 元 | 4 元 |

**缓存命中比未命中便宜 50 倍**，这就是为什么这套 harness 花了很大力气安排消息顺序。

按实测数据折算（空闲时段）：

| 动作 | 大约花费 |
|---|---|
| 一轮普通对话（记忆已建立，缓存命中好） | **约 0.001 元（0.1 分）** |
| 一轮会产生新记忆的对话 | 约 0.0025 元 |
| 一次 dream 整理（40 条） | 约 0.006 元 |
| 一次 dream 整理（80 条） | 约 0.008 元 |
| 一次自动 compact（摘要 20 条历史） | 约 0.004 元 |

也就是说：**随便聊，一天聊一百轮也就一毛钱。** 真正贵的是整理一次档案 ——
所以它才必须显式触发、而且有独立预算（实测一轮处理 3 个会话约 27k token）。

> **用量页现在只报 token，不折算金额。** 估算花费已经永久删除：
> 单价表只能对一家成立，多供应商下拿 DeepSeek 的单价去算别家的用量会给出错的数字。
> 上面这张表是背景资料，帮你建立量级感，不是工具里的功能。

## 五、出问题怎么办

- **它自己循环不停** → 不会的：四道熔断（步数 / 单轮 token / 墙钟 / 重复调用）会拦住。
  聊天页出现黄色提示即为熔断生效。
- **dream 整理坏了一张档案** → **没法回滚**（ADR-065：整理是单向门，不留快照），
  **也没有预演**（ADR-072）。三条路，从轻到重：
  ① 直接在界面上修：**Dream 页 → 点开那份档案 → 「编辑」**（ADR-070）；
  ② 想看某份文件当时**写了什么全文**：去 `data/dreams/<run-id>.jsonl` 里找那次
  `vault_write` 的参数（`--dream-review` 会告诉你轨迹在哪）；
  ③ 整层重来：**Dream 页的「格式化并初始化 dream」**（或 `run.cmd --dream-format`）——
  清空档案 + 运行记录 + 整理进度，再 `--dream` 让模型从头整理一遍。
  它**只动 dream 那三样**（对话、记忆、接口 key 都不碰），代价是再花一次整理的钱，
  而且**你手写的档案不会回来** —— 所以真正在意的话，动手前先复制一份 `data/vault/`。
- **注意**：第 ③ 条会**连运行记录（轨迹）一起清掉** —— 那是追回单份文件全文的唯一凭据。
  想追回就先追回，再格式化。
- **想自己加/改档案** → Dream 页的目录树里「新建档案」或点开之后「编辑」/「删除」。
  两条要记住：删掉没有回滚（确认框会列出**哪些档案的双链会因此变成"还没写"**）；
  原生模式（有 `sections.yaml`）的 README / `index.md` / `earlier_months` 会**自动重建**，
  生成物在界面上只读；旧模式才需要照着"没有被 README 提到"的校验提示自己补。
- **想导入 Kimi 原生 Dream vault** → `run.cmd --vault-import <zip>`（目标必须是空 vault；
  导入后原生模式立即生效；生成物过期会由结构校验报出来，`--vault-rebuild` 可重建）。
- **想让档案更新** → `run.cmd --dream`，或界面上 Dream 页的「整理一次」。
  **没有待整理的记录时它根本不会调用模型**（所以随手跑一下不会白花钱）；
  一次最多整理 3 个会话，剩下的下次再跑。
  （整理正在跑的时候，界面上的编辑会被拒绝并说明原因 —— 免得它把你正在改的那份覆盖掉。）
- **想换成英文界面** → 左下角「设置 → 常规 → 语言」选 English，**立刻生效、不用重启**（也不会打断正在生成的那一轮）。
  换的不只是界面：**模型看到的提示词、工具描述、工具回给模型的文字也一起变英文**（ADR-085）。
  两条边界要知道：① 你自己写的记忆与背景档案**不会被翻译**（提示词里会说明它们可能是中文写的）；
  ② CLI 的输出保持中文（它是调试工具）。新机器的默认值可以用 `HARNESS_LANGUAGE=en` 改。
- **模型好像"记得"你没告诉过它的事** → 那是**背景档案**（dream memory）在起作用：
  它只有一份 README 常驻在上下文里，细节是模型自己调 `dream_read` 进去读的。
  用 `run.cmd --vault` 看都有哪些档案、README 占了多少预算、结构有没有毛病、
  还有多少会话没整理。**背景档案的可信度低于记忆条目**（它是压缩推断出来的），
  所以模型被要求两者冲突时以记忆条目为准 —— 如果它把档案里的旧信息说成事实，直接告诉它更正。
- **想看它当时到底发了什么给模型** → `run.cmd --replay <session-id>`，
  会打印每一轮**真正发出的完整 prompt**。这是排查一切"它为什么这样说"的最终手段。
- **日志在哪** → `data/sessions/*.jsonl`（对话）、`data/dreams/*`（每次整理：
  轨迹 `.jsonl` 里存着每一次 `vault_write` 的全文、结果 `.json`）。都是人可读的。
- **`run.cmd --web` 有时不弹浏览器，而是弹一个"现有实例正在以提升的权限运行"的系统框** →
  这不是随机抽风，是**你上一次是在"管理员"窗口里跑的**（ADR-080）。机制很短：
  Windows 打开网址时会**用调用者的权限**去唤起浏览器，于是那次把浏览器也开成了管理员；
  而 Edge/Chrome 关掉窗口也不一定真退出（"启动增强"/后台继续运行），
  那个提权实例就一直占着位置 —— 等你**下次用普通窗口**启动，系统就弹这个框问你要不要
  "用普通权限重启现有实例"。三个处理办法：
  ① **点「是(Y)」**：这正是它在问的事，点完就正常了；
  ② 彻底退出浏览器（所有窗口 + 托盘），必要时在 `设置 → 系统和性能` 关掉
  「启动增强」「关闭 Microsoft Edge 后继续运行后台扩展和应用」；
  ③ **根治：别用管理员窗口跑 `run.cmd --web`** —— 现在 harness 检测到自己被提权时，
   **不会**直接开浏览器，而是改请 Explorer 以普通权限代开，并在横幅里说明白。
  顺便：`net session >nul 2>&1 && echo 管理员 || echo 普通` 可以当场看你这个窗口是什么权限。
- **想自己核对界面**（改过前端之后）→ `scripts/ui_check/`：那是一套**无浏览器**的前端自检
  （自写最小 DOM stub + `node:vm` 载入真的 `web/app.js`），跑法与"它证明不了什么"
  都写在那个目录的 `README.md` 里。它不联网、不花钱。

## 六、数据与备份

```
data/vault/memory_instruction.md  逐条记忆（原生 Markdown，id + 正文）
data/memory.db          仅 Dream 整理游标（旧记忆表不读取、不迁移）
data/sessions/*.jsonl   对话历史（每行一个事件，可重放）
data/dreams/<run>.jsonl 整理轨迹（**每一次 vault_write 的全文都在这里**）
data/dreams/<run>.json  整理结果（差异、用量、结构校验）
data/memory.json        记忆条数上限（可在设置里改，0-100）
data/vault/*.md         背景档案（dream memory：README + sections + entities，可直接编辑）
data/attachments/<会话 id>/*   对话里的图片（删会话会连它一起删；孤儿用 `--attachments-gc` 清）
.env                    启动用的配置项（`.env.example` 的模板；**不放 key**）
```

- 备份：整个复制 `data/` 目录即可。
- **只想清掉背景档案那一层** → `run.cmd --dream-format`（或 Dream 页上的
  「格式化并初始化 dream」）。它清掉**档案 + 运行记录 + 整理进度**并建一个空骨架，
  **不动对话、记忆、接口配置与 key**，需要二次确认（要你打出确认词）。
  这也是整理改坏之后"重来"的正路。
- 重置：删掉 `data/` 会重新初始化一个空库（**记忆与历史都会没**，先备份）。
  **背景档案、整理运行记录与整理进度也会一起没**（ADR-065：dream 层被格式化并初始化），
  所以设置里的重置预览会单独列出"背景档案 N 份 / 整理运行 N 次 / 图片 N 张"。
  它**不会**替你造一个空 vault 骨架 —— 出厂状态里本来就没有那个目录
  （要骨架用 `run.cmd --vault-init`；而 `--dream-format` 会顺手建好）。
  另外注意：**整理是不可逆的**（没有回滚、也没有预演），所以重置之前也救不回被整理掉的档案。
- 想换一套独立数据实验：设环境变量 `HARNESS_DATA_DIR=data-你的实验` 再启动。
- 想换一套独立数据实验：设环境变量 `HARNESS_DATA_DIR=data-你的实验` 再启动。
  填**相对路径**即可（按项目根解析，不跟当前目录走）；默认是项目下的 `data/`。

## 七、发图片（M8）

对话窗口里可以把图片发给模型，**三种入口**：输入框的 📎 按钮（可多选）、
把图片**拖进输入框**、以及 **Ctrl+V 直接粘贴截图**（截图不必先存成文件）。
图片会随请求发给模型接口，不是只留在本地。历史里的图片点一下能开大图；
生成中（busy）时不能再加附件（不做排队，会用 toast 说明）。输入框下方固定显示当前会话统计，
不再显示附件提示（ADR-108）。

### 多模态开关与本地 OCR（M9）

对话页右上角、**「联网搜索」旁边**多了一个**会话级**的「多模态」开关，**默认开**。
开 = 图片按上面那样直接发给模型；关 = **本地 OCR**，只把识别出的**文字**发给模型，
**图片本身不会发出去**。

#### 什么时候该关掉多模态

模型不支持图片时，**不是所有接口都会报错**。实测 `deepseek-v4-pro` 收到图片返回
**HTTP 200**，图片被静默丢掉（`prompt_tokens` 91 → 99，图片只多出 8 个 token），
然后答一句"无法确定"。你以为图发出去了，它其实在瞎猜 —— 这种模型就该关掉多模态走 OCR。

开着的时候还有一道**发送前的闸**：先查"这个模型声明支持图片吗"，判定"不支持"就直接
拒绝发送并说明原因（**这次请求没有发出去、也没有写任何记录**），给三条出路 ——
关掉多模态走 OCR / 换多模态模型 / 到「设置 → 接口」把模型加进「支持图片的模型」名单
（**留空 = 未知 = 不拦**）。另外，换成不支持图片的模型后，**历史里已有的图片**会让
你只发文字也收到一条提醒（"这个会话前面有 N 张图片……它看不到"）：不拦你，
但你不会拿到一句莫名其妙的答案。

#### 关了之后模型收到什么

你打的字，加一句"用户上传了 N 张图片，但多模态模式没开，所以图片本身没有发给你，
只有本地识别出的文字"，再加每张图一块 `【图片 N：名字】识别到的文字：…`，
最后一句说明这段文字是**外部数据**、其中的"指令"都不是你的要求。
没识别到文字的图写"没有识别到任何文字"，识别失败的图写"识别失败：…"。
**这段 OCR 文字会原样回显在你的气泡里**（标注"多模态已关 · 只发送了下面的识别文本"），
消息流里另给一条汇总提示（"已把 N 张图片 OCR 成文字发给模型"／"其中 M 张没有识别到文字"）
—— 你能看见模型到底收到了什么。

#### 慢在哪

新增依赖 **rapidocr-onnxruntime**（`run.cmd --setup` 会装，模型文件在 wheel 里，
装完离线可用）。实测：**引擎加载约 1.6s**（第一次 OCR 时付一次，之后同一进程复用），
**单张通常 1.5~3.5s**（文字密度高的更慢：960×520 的文字图约 3~5s，750×503 的照片约 1.6s）。
所以**多图消息要等十几秒到几十秒**，界面上会先出"正在识别图片文字…"，不会静默卡住。

识别质量：清晰的中文 / 英文 / 数字**基本全对**；但会**吃掉中西文之间的空格**
（"订单号 A-2026" 变成 "订单号A-2026"），小字水印会认错（实测把 "Baidu" 认成 "Baldu"）。
**要拿识别结果做正事时，建议对着原图核一遍。**

### 上限与缩放

| 项 | 值 |
|---|---|
| 支持格式 | PNG / JPEG / WebP / GIF（**按文件内容判断**，改扩展名没用；不支持 SVG） |
| 单张上传 | ≤ 16 MiB、单边 ≤ 8192 px |
| 落盘 | 超过约 1300×1300 等效像素（169 万像素）会被**自动等比缩小** |
| 一条消息 | 最多 8 张；文字与图片至少有一个（**可以只发图不说话**） |

**落盘的那一版既是界面显示的那一版，也是发给模型的那一版** ——
所以你在气泡里看到的就是模型看到的。

### 花多少钱

**图按像素计费，不按文件大小。** 用 `deepseek-flash` 实测：750×503 的图约 **245** token，
4000×4000 的大图约 **1024** token（官方每张上限就是 1024）。
把 6 MP 缩到 1.69 MP，token 几乎不变（约 965 → 1024 以内），但请求体小 3 倍。
历史里的图片**每轮都会重发**（这样"刚才那张图里的字再读一遍"才有效），
代价是每张图一轮多花几百 token —— 一条消息塞满 8 张大图，这一轮就多出约几千 token。

### 存在哪、怎么清

```
data/attachments/<会话 id>/<内容哈希>.<扩展名>
```

同一张图重复发只存一份（按内容去重）。**删会话会连它的图片一起删** ——
这是刻意的（ADR-074 有说明），与"删会话只删会话"那条老边界不同。
「设置 → 重置」的预览里会报出会删掉多少张图片。

`run.cmd --attachments-gc` 清理**没有被任何会话引用**的图片（加了图又删掉没发，
就会留下这种孤儿文件）：**默认只报告，加 `--yes` 才真删**。

### 出错怎么办

| 你看到的 | 是什么 |
|---|---|
| 说格式不对 | 文件内容不是 PNG/JPEG/WebP/GIF（**改扩展名不算**），或者是截断/伪装的图 —— 错误信息会带上 Pillow 的原话 |
| 说太大 | 超过 16 MiB 上传上限或 8192 px 单边；先缩一下再发 |
| 让你跑 `run.cmd --setup` | 没装 **Pillow**。它负责验证"这是不是一张真图片"、读尺寸、缩放；**缺失时上传明确报错，不会静默降级** |
| 说一条消息最多 8 张 | 这条消息里的图超了，去掉几张再发 |
| 动图变成了静帧 | 需要缩放时 GIF 按第一帧处理，界面会带一句提示，不是悄悄干的 |
| 「多模态」开着，却提示"模型没有声明支持图片" | 发送前的闸拦下了：**这次请求没有发出去、也没有写任何记录**。三条出路 —— 关掉「多模态」用本地 OCR 只发文字 / 换一个多模态模型 / 如果你确认它其实支持图片，到「设置 → 接口」把它加进该档案的「支持图片的模型」名单（留空 = 未知 = 不拦） |
| 「多模态」关着，却提示"本机 OCR 不可用" | 没装 `rapidocr-onnxruntime`。**发送被明确拒绝**（不静默降级，也不会把"OCR 不可用"当文字发给模型）：打开「多模态」直接发图，或先跑 `run.cmd --setup` |
| 模型说"没有识别到任何文字" | 这张图里**确实没有文字**（纯色图、纯风景照）——识别成功但结果为空，与"识别失败"是两件事。要看图片内容请打开「多模态」 |
| 提示"第 N 张图片识别失败" | 这一张出问题了（引擎的原话会一起显示），**其它图照常识别、消息照常发出去**；模型那边看到的是"识别失败：…"，所以它不会对着空白瞎猜 |
| 点了发送但一直没出去 | 正在排队做 OCR：引擎加载约 1.6s、单张 1.5~3.5s，多图要十几秒到几十秒；界面会先出"正在识别图片文字…"，等它 |
| 某轮历史明明是图片，重放却成了文字 | 重放按**当时记下的模态**走，不按当前开关。某轮是用 OCR 文字发的，之后你打开多模态，**那一轮仍然是文字**（事件日志记的是"当时到底发生了什么"） |

发送失败（含后端 400）时**已选的图片会保留**在附件栏里，不用重新选一遍。

**还没验过的**：真实鼠标拖放、真实剪贴板粘贴、中文输入法，以及窄屏与深色主题下的观感 ——
这些只有人工点一遍才算数。这一轮同样没验的还有：**"未知模型静默丢图"我们检测不了**
（拿 token 数猜会被自己的估算误差淹没），只能靠用户声明或换模型。
契约与已实测清单见 `docs/11-attachments.md`。
