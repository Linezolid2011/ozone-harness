# 14 · 提示词可编辑（每语言独立 + 每条可复原 + 出厂复原）

## 0. 一句话

「设置 → 提示词」里的每一条都能**改**，改动存在 `data/prompts.json`；
**中文与英文各存各的**（改中文绝不影响英文）；每条各有一个**复原**按钮
（回到内置原文）；**恢复出厂设置**把这门/两门语言的自定义一起抹掉。

## 1. 用户的四条硬要求，各自落在哪

| 要求 | 落点 |
|---|---|
| 提示词可编辑 | `POST /api/prompts/update` + 界面上的编辑器 |
| 恢复出厂设置能复原提示词（中英都要） | `data/prompts.json` 就在 `data/` 里，重置整目录删掉即复原；**重置预览要如实报出会失去几条自定义** |
| 每条各有复原按钮 | `POST /api/prompts/revert`（带 `id`）+ 卡片上的「复原」；「已修改」标记 |
| **改中文不影响英文** | ① 文件里按语言分家；② 写入是**读-改-写整个文件**（只改自己那门）；③ 专门有测试逐字节比对另一门没被动过 |

## 2. 存储：`data/prompts.json`

```json
{
  "version": 1,
  "zh": { "SYSTEM_PROMPT": "把内置那段换成了我自己的……" },
  "en": {}
}
```

* **只存改动过的那几条**（没改的不进文件）—— 这样内置文案将来改进时，
  没被覆盖的那些会跟着一起更新；
* 写入是 `写临时文件 → os.replace`（与 `settings.json` / vault 同一套）；
* **不认识的键原样保留**（以后加字段要能兼容）；顶层 `version` 供将来迁移；
* **坏文件 fail-soft**：解析不了/结构不对时**照常用内置**，并把这件事如实报出来
  （`GET /api/prompts` 的 `store_error`，页面上显示一行警告）——
  绝不能因为一个坏文件让整个程序起不来（同 ADR-064 的"坏数据不许让整条流水线停摆"）。

## 3. 生效路径（关键：一行调用点都不用改）

`harness/prompts/__init__.py::bundle()` 从"返回语言模块"变成
**返回"内置 + 覆盖"的生效副本**（一个只读的名字空间）：

* 所有取文案的地方**早就**统一走这个入口（`context.py` / `dream.py` / `loop.py`
  都是 `from .prompts import bundle`），所以**没有任何调用点需要改**；
* 载入时机：`i18n.apply_settings()` 里顺带 `prompts.configure(settings.data_dir)` ——
  那是 CLI 与 Web 两个入口**都已经在调**的那一处（"每个入口必须调一次"的东西
  只能有一个入口，否则迟早漏一个，见 ADR-072 的教训）；
* **变更检测**：每次 `bundle()` 用 `(mtime_ns, size)` 判断文件变没变，
  变了就重载 —— 所以**你手工编辑 `data/prompts.json` 也立刻生效**；
* `i18n.bundle()` 保留为"拿语言模块"的**底层原语**（不叠加覆盖）；
  应用代码不许直接调它（有守卫测试盯着）。

## 4. 接口

### 4.1 `GET /api/prompts`（在原有基础上增量）

每个提示词条目**新增**：

| 字段 | 含义 |
|---|---|
| `default_text` | **内置原文**（恒定，用于对比与"填入内置内容"） |
| `overridden` | 这一条现在是不是被用户改过 |
| `warnings` | 保存后仍存在的问题（见 §5），现在为空数组 |
| `placeholders_missing` | 内置里有的占位符，现在这条里没有（会导致对应内容不再注入） |

顶层新增：

| 字段 | 含义 |
|---|---|
| `overrides` | `{"zh": ["SYSTEM_PROMPT", ...], "en": [...]}` —— 两门语言各自改了哪些（**界面上"改中文不影响英文"就靠它显示**） |
| `store_error` | 文件坏了的话这里是那句人话，否则 `""` |

`summary` 新增 `overridden`（当前语言里改过几条）。

### 4.2 保存

```
POST /api/prompts/update   {"language": "zh", "id": "SYSTEM_PROMPT", "text": "……"}
→ 200 {"ok": true, "language": "zh", "id": "SYSTEM_PROMPT",
        "overridden": true, "warnings": ["……"], "stored": true}
```

`stored: false` 表示"这段文本与内置一模一样，所以没存成自定义"（见 §5 最后一条）。

### 4.3 复原

```
POST /api/prompts/revert   {"language": "zh", "id": "SYSTEM_PROMPT"}   → 复原这一条
POST /api/prompts/revert   {"language": "zh"}                          → 复原这门语言的全部
→ 200 {"ok": true, "language": "zh", "cleared": 1, "overridden": false}
```

**`id` 缺省 = 复原这门语言的全部**（一个接口两种粒度，省掉一组几乎同名的路由）。
复原一条**没被改过**的条目不是错误（幂等，`cleared: 0`）。

## 5. 校验：什么拒绝、什么只警告

判据是"**保存之后下一次发请求会不会出问题**"。

| 情况 | 处置 |
|---|---|
| `language` 不认识 | **400**（"不认识的取值要明确报错"，不许悄悄当成默认语言 —— ADR-085 的教训） |
| `id` 不是这 22 条之一 | **400** + 报出合法 id 的个数（不是列表，太吵） |
| 文本去空白后为空 | **400**："留空不等于删掉它 —— 想回到内置用「复原」" |
| 超过 `prompts_max_chars`（默认 20000） | **400** + 报出实际字符数与上限 |
| **不是合法的 format 串**（如 `{`） | **400** + 那句 `string.Formatter` 的话 |
| **引入了内置里没有的占位符**（如 `{foo}`） | **400**："这条内置文案里没有 `{foo}`，填进去会在**发送时**报错" —— 这是最危险的一类：它不会在保存时报错，而是在下一轮对话里炸 |
| **少了内置里有的占位符**（如 `{memory_text}`） | **200 + warning**："`{memory_text}` 不在了：记忆条目不会被注入"。**不拒绝** —— 用户可能就是想这么改，但必须让他知道后果 |
| 与内置**逐字相同** | **200**，但 `stored: false`，并把那条已有的覆盖**删掉** —— 免得留下一份"和内置一样却把内置冻结了"的覆盖 |

**这些报错与警告是双语的**（`ui.prompts.err.*` / `ui.prompts.warn.*`）：
它们由后端回给界面、界面按"显示后端原话"处理，所以英文界面下看到的就是英文。
这一处曾经是**中文字面量**（英文界面会跳出一句中文的失败原因）——
是前端 agent 在核对截图时发现并上报的，现在有 `MessageLanguageTests` 钉着。

## 6. 语言隔离（这条是硬要求，怎么保证、怎么测）

**保证**：

1. 文件里 `zh` / `en` 是两个独立的 map，键就是 22 个提示词的常量名；
2. 写入路径永远是：读出整个文件 → 只改 `data[language][id]`（或只删
   `data[language]` 里的键）→ 整个写回；
3. 界面上一页只显示**当前语言**的条目，所以"改中文"这条路径根本碰不到 `en` 的键。

**测试**（比"我看过了"硬）：

* 存一条中文覆盖，然后**逐字节**比对 `prompts.json` 里 `en` 那部分没变；
* 反向再来一次（先有英文覆盖，再改中文，英文仍在且内容不变）；
* `revert(language="zh")` 之后，英文覆盖**还在**；
* 两门语言同时有覆盖时，`bundle("zh")` 与 `bundle("en")` 各拿各的。

## 7. 与其它"清空"操作的关系

| 操作 | 对提示词的影响 |
|---|---|
| 恢复出厂设置 | **抹掉**（`data/` 整个没了）→ 就是"复原提示词（中英都复原）"。**重置预览里要报出会失去几条自定义** |
| `--dream-format` / 「格式化并初始化 dream」 | **不碰**（它只管档案 + 运行记录 + 整理进度）。提示词不是 dream 层的东西 |
| `--vault-init` | 不碰 |

## 8. 前端要求

1. 每条提示词卡片上：
   * 被改过时显示**「已修改」标记** + **「复原」按钮**（走 `POST /api/prompts/revert`，
     二次确认；确认文案里要写明"复原的是**当前语言**这条"）；
   * **「编辑」按钮** → 变成编辑器（`<textarea>` 装当前生效文本 + 保存 / 取消）；
     编辑器里给三句提示（各自的 key）：
     ① 哪些占位符会被填（`placeholders`）——**别删掉它们**；
     ② 改完**下一条消息的提示词缓存会重建**（一次性的钱）；
     ③ 被改过的条目会**冻结**：内置将来改进了它也不会自动跟进，想跟进就点「复原」。
   * 被改过时，除了"当前生效"的原文折叠块，再给一个**「内置原文」**折叠块
     （用 `default_text`），好让人对比；
   * `warnings` / `placeholders_missing` 非空时，在卡片上显示一行**警告**
     （不是错误色，用 warn 色）—— 这是"保存成功了但有后果"的提示。
2. **「把这门语言的提示词全部复原」在页首右上角、而且是红色的**（走 `revert` 不带 `id`），
   二次确认文案里要写出**语言名**与**条数**。
   〔用户改过一次位置：第一版按契约放在"分节标题下面、分组上面"，用户看了截图说
   *"红圈里的这个按钮移到蓝圈的位置并且做成红的"* —— 也就是**页首那一行的右端**，
   与"共 22 条提示词 · 16 个工具定义"同一行（`.prompts-head` + `.prompts-actions`），
   配色用既有的 `btn-danger`。理由站得住：它一次动一整门，本来就是危险动作；
   而原来的位置夹在标题与分组之间，不显眼。〕
   这门语言**一条都没改**时它是**禁用**的（没有东西可复原），`title` 说明为什么 ——
   一个能点、点了却什么都不做的按钮比没有更糟。
   `dom-stub` 里钉住了这两件事（`btn-danger` + 在 `.prompts-head` 里且排在文字列之后）。
3. **语言隔离要在界面上看得见**：`overrides` 里两门语言各改了几条，就在
   页首统计里分别写出来（例如「中文已改 2 条 · 英文 0 条」）——
   用户最担心的就是"改中文把英文带坏了"，那就让他在同一屏里看到英文没被碰。
4. `store_error` 非空时，页首显示一条醒目的警告（文件坏了、现在用的是内置）。
5. i18n：新文案进 `web/i18n.js` 的两份 catalog（必需的那几个 key 见 §8.1）；
   文案里**不许出现**另一门语言的字（en 里不许有汉字，已有守卫）。

### 8.1 必需的 i18n key（其余自定，但每个都要有引用点）

`prompts.edit` / `prompts.edited` / `prompts.revert` / `prompts.revert_all` /
`prompts.revert_confirm` / `prompts.revert_all_confirm` / `prompts.revert_done` /
`prompts.revert_all_done` / `prompts.save` / `prompts.saved` / `prompts.save_failed` /
`prompts.editor_hint_placeholders` / `prompts.editor_hint_cache` /

## 9. 不变量与测试

后端（`tests/test_prompts_edit.py`）：

1. **生效**：覆盖之后 `context.build_system_message()` 里真的是自定义那段；
   `dream.build_dream_system_message()`、`context.build_tail_message()` 同理
   —— 一条覆盖若只改界面不改行为，这个功能就是假的；
2. **语言隔离**（§6 的四条）；
3. 校验表（§5）逐条：拒绝的四种 + 警告的一种 + 与内置相同的那种；
4. 复原：单条 / 整门；幂等；没被改过时 `cleared: 0`；
5. **恢复出厂**：重置后 `data/prompts.json` 没了、提示词回到内置；
   重置预览里 `prompt_overrides` 的数字正确；`perform_reset` 真跑一遍；
6. **`--dream-format` 不碰提示词**（改过提示词 → format → 提示词还在）；
7. 坏文件 fail-soft（内置生效 + `store_error` 非空 + 程序不炸）；
8. **手工改文件会被重载**（写完文件 → 下一次 `bundle()` 就是新的）；
9. 出厂/API 的输入边界（不认识的语言 / id、空文本、超长、坏占位符）。

守卫：**应用代码不许直接调 `i18n.bundle()`**（只有 `harness/prompts/__init__.py`
可以）—— 否则那条路径会绕过用户覆盖，而且是静默的。用 `tests/test_paths.py`
那种"扫源码"的写法。

接口（`tests/test_web.py`）：GET 的增量字段、update/revert 的 200/400、
POST 的两道闸（同源 + JSON）。

前端（子 agent）：`dom-stub` + `e2e-live` 各加断言 —— 至少"改一条 → 卡片出现
「已修改」+「复原」"、"复原 → 标记消失"、"警告显示出来"、
"两门语言各自的计数显示正确"、"编辑器里的提示三句都在"。

## 10. 不做的事（写清楚，免得以后当成漏了）

* **工具定义不可编辑**：这一轮只做 22 条提示词。工具的描述与参数 schema 是
  代码里的契约（还牵着 i18n 的成对守卫），改它们要另开一轮、另写一份契约；
* 不做版本历史 / diff 视图（只有"当前 vs 内置"两份）；没有多套预设；
* 不记忆"上次展开/编辑到哪"（折叠状态仍是零 JS 状态）；
* 不动 `harness/prompts/{zh,en}.py` 里的内置常量：那是**默认值**，
  也是 `tests/test_i18n.py` 的守卫对象（"英文里没有汉字"只管内置，不管你的覆盖）。
