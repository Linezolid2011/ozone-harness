# 12 · 界面语言（zh / en）

> 本文件是**接口契约**：后端、前端、以及每一个"要翻译的地方"都按它实现，
> 谁都不许"顺手"改形状。动机与取舍见 `docs/01-decisions.md` 的 ADR-085。

## 0. 一句话

设置里可以选**中文 / English**。切到英文时，**界面文案 + 模型看到的每一段非用户文字**
（系统提示、工具描述与参数、工具回给模型的文本、后端的 notice 与错误）全部是英文；
**用户与模型写的内容**（记忆条目、背景档案、历史对话）原样不动，但提示词里会说明
"这些内容可能是中文写的"。

## 1. 什么翻、什么不翻（这条决定了后面所有细节）

| 翻 | 不翻（刻意） |
|---|---|
| Web 界面的全部文案（含 `index.html` 里的静态字、按钮、提示、toast、确认框） | **用户数据**：记忆条目、背景档案正文、历史对话、附件文件名 |
| 系统提示、README/记忆注入的**框架文字**、末尾的时间与裁剪提示 | **用户自己输入的内容**（永远原样） |
| 工具 `description` 与 `parameters` 里的描述文字 | 工具的 **`name`**（`mem_create` 等是 API 契约，永远英文） |
| 工具**回给模型**的文本与错误（`payload.error` / `payload.note` /…） | 事件 `kind`、JSON 字段名、文件路径、`data/` 下的日志与轨迹 |
| 后端的 notice 与错误（发给界面的那些） | **CLI 的输出**（它是开发/调试工具，保持中文；见 ADR-085） |
| 危险动作的确认词（`格式化` ↔ `format`） | 代码注释、docstring、测试名、`docs/` |

**一处例外要说清**：工具结果的 `display` 字段是给 CLI 看的一行简报 → 跟着**界面语言**走
（不是固定的中文），因为它和 notice 一样是"给人看的一句话"。

## 2. 设置存在哪

* 运行期值：`data/settings.json` → `{"language": "en"}`（**读操作不创建文件**）
* 默认值：`HARNESS_LANGUAGE`（默认 `zh`）。取值容错：`en` / `en-US` / `English` → `en`；
  `zh` / `zh-CN` / `中文` → `zh`；认不出来的退回默认值（同 `_int_range` 的口径：
  环境变量是种子，写坏了退回默认，不该让程序起不来）
* 恢复出厂设置会把它一起抹掉 → 回到默认
* **改了立刻生效**：下一轮构造提示词时就是新语言（每次都用 `i18n.current()` 现取）

## 3. 后端的机制（`harness/i18n.py`）

```python
i18n.LANGUAGES            # ("zh", "en")
i18n.normalize(value)     # 任意输入 → "zh" / "en"
i18n.current()            # 当前语言
i18n.set_language(value)  # 切（返回规范化后的值）
i18n.use(value)           # 上下文管理器：测试用，退出时还原
i18n.t(key, **kw)         # 短文案：查 MESSAGES，缺了退回中文，两边都没有就 KeyError
i18n.bundle()             # 长模板：当前语言的 prompts 模块
i18n.register(lang, mapping)
```

**为什么是"当前语言"这个全局状态**（而不是给每个函数加 `lang` 参数）：
模型侧文案散落在 20 个模块里，而单用户机器上语言是**应用级**的。
把每个函数签名都改一遍，收益只是"同一进程里中英并存" —— 那正是我们不需要的。
代价（写进 ADR）：一个进程里只有一个语言，切换发生在两轮之间。

### 长模板：`harness/prompts/{zh,en}.py`

模块级常量（五十行的提示词塞进字典没法读）。**两个模块必须暴露同名同占位符的常量**：

```
SYSTEM_PROMPT  VAULT_PROMPT  VAULT_EMPTY_PROMPT  VAULT_NO_README_PROMPT
WEB_SAFETY  WEB_TOOLS_PROMPT  OPEN_ONLY_PROMPT
SUMMARY_HEADER  COMPACT_SYSTEM_PROMPT
DREAM_SYSTEM_PROMPT  DREAM_INSTRUCTION
```

代码里一律 `bundle().SYSTEM_PROMPT.format(...)`，**不许**再 import 某个具体语言模块
（`harness/context.py` 不再定义这些常量；测试要断言中文原文就 `from harness.prompts.zh import ...`）。

### 短文案：按子系统成对放置

| 文件 | 谁的内容 |
|---|---|
| `harness/tools/text_zh.py` / `text_en.py` | 工具描述、参数说明、工具回给模型的文本、`display` |
| `harness/ui_text_zh.py` / `ui_text_en.py` | 发给界面的 notice 与错误（`web.py` 的路由错误、附件/OCR/重置/档案路径/语言设置），**以及模型侧的"包装行"**（记忆注入的框架文字、OCR 边界块、整理记录行）—— 它们短、且与界面文案同源，放一起更好维护 |
| `harness/net/text_zh.py` / `text_en.py` | 联网工具的失败文案（**会作为工具结果回给模型**） |
| `harness/provider_text_zh.py` / `provider_text_en.py` | 供应商/接口层与运行期装配的报错（显示在设置页、也会作为 400 原话回到界面） |

每个文件只导出 `LANG = "zh"|"en"` 与 `MESSAGES: dict[str, str]`（值里可以有 `{}` 占位符）。
**一个 key 只能在一处定义** —— 两处定义了同一个 key 会被守卫测试拦下。
跨子系统复用（比如工具要用档案层的路径错误）→ 用 `ui.*` 里的那个 key，不要复制一份。

**"长模板"与"短文案"的分界**：五十行一段、带小标题的（系统提示、整理提示、压缩提示、
末尾时间/裁剪提示、摘要渲染前缀）→ `prompts/`；一两行的、或散在各模块里的 → 成对的 catalog。

### key 命名

```
tool.<工具名>.desc              工具描述
tool.<工具名>.param.<参数名>     参数说明
tool.<工具名>.<情形>             工具结果/错误（如 tool.vault_write.created）
web.<区域>.<名字>                路由层错误（web.error.no_provider / web.dream.busy …）
ui.<区域>.<名字>                 通用界面文案（ui.vault.bad_path / ui.attachment.too_big …）
```

## 4. 接口

```
GET  /api/settings/language   → {"language":"en","languages":["zh","en"],"default":"zh"}
POST /api/settings/language   {"language":"en"}
                              → 200 {"ok":true,"language":"en","languages":[...],"default":"zh"}
                              → 400 {"error":"<人话>"}   取值不认识时
GET  /api/config              → 多一个 "language" 字段、一个 "timezone" 字段与一个
                                "max_output_tokens" 字段（前端启动时就知道该显示哪种语言、
                                哪个时区、单轮最多输出多少）
```

POST 只改语言，**不动别的设置**；同源 + `Content-Type` 两道闸由既有的 `do_POST` 负责。

## 5. 前端

* `web/i18n.js`（新文件，**在 `app.js` 之前**加载，零构建）导出：
  `I18N.languages`、`t(key, vars)`、`setLanguage(lang)`、`applyStaticTexts(root)`、`current()`
* `index.html` 的静态字走 `data-i18n="key"`（可带 `data-i18n-title` / `data-i18n-placeholder`），
  由 `applyStaticTexts()` 填 —— 这样"换语言"不必重建整页。
  **实现里多了一种：`data-i18n-html`**（契约原本没列，实现时加的）：Dream 页那几段说明含
  `<strong>` / `<code>`，用 `textContent` 会把标记吃掉。**只在这类"静态、且值由我们自己写死"的
  地方用它** —— 任何可能掺入用户/模型内容的地方一律 `textContent`（那是 XSS 防线）。
* **不在静态标记里的那几处**（`#brand-sub` / `#sessions-label` / `#chat-title` /
  `#composer-hint` / 两个开关的 label / `#multimodal-hint`）：它们的字由 `app.js` **按状态**
  渲染，挂上 `data-i18n` 会被一个与状态无关的常量盖掉。HTML 里保留中文兜底字
  （JS 还没跑完时页面也是对的）。
* 切语言的落点：设置 → **常规 → 语言**（`PANES` 里是 `general`，`renderLanguagePane`
  画其中"语言"那一段；主题 / 时区 / 单轮最大输出三段并排，见 ADR-099 / ADR-101），
  两个选项（中文 / English）
* **原地重渲染**（用户明确选了这条，不刷新页面）：POST 成功后调
  `rerenderForLanguage()`，它至少要把这些重新跑一遍：
  1. `applyStaticTexts()`（含 `document.title`）；
  2. 会话列表、顶部品牌行、模型/档位选择器、两个开关（联网 / 多模态）与它们的提示句；
  3. 输入框占位符、附件区、发送/停止按钮；
  4. 当前设置子页（记忆 / Dream / 用量 / 接口 / 工具 / 提示词 / 常规 / 重置）；
  5. 当前会话的消息流 —— 用 `/api/sessions/<id>` 重新渲染一遍，
     这样消息里那些**由后端产出的标签**（步数/用量/工具简报/压缩摘要）也跟着换语言；
     重放不出历史里的临时 notice 是已知代价（它们是当时那一刻的话）。
* 语言状态放 `state.language`；`init()` 从 `/api/config` 拿初值
* **生成中不许切**：语言是进程级的，切换后同一轮里后续每一步都会用新语言重新组装提示词 ——
  模型会在一次回答中途看到"系统提示换了一套"。所以 `state.busy` 为真时「语言」那两个选项
  **禁用并说明原因**（"正在生成回答，等这一轮结束再切换"），生成结束后恢复。
  这一条是刻意不做服务端硬闸的：单用户本机程序，界面上一个禁用比加锁简单得多。

## 6. 守卫（`tests/test_i18n.py` + 前端自检）

后端（机械的，不靠人眼）：
1. 两个语言的 key 集合**完全一致**（每个 catalog 都查）；同一个 key 不许在两处定义；
2. 每个 key 在两种语言下都能 `t()` 出来；
3. `prompts.zh` / `prompts.en` 的公开常量名一致、每个常量的 `{}` 占位符集合一致、
   用假值 `format()` 都能成功；
4. **英文输出里一个汉字都没有** —— 对系统提示、末尾提示、压缩提示、整理提示、
   每个工具的描述与参数、每个 `MESSAGES` 的值都查一遍（这是"漏翻"的唯一可靠判据）；
5. 切换语言后，`build_system_message()` 的产物确实变了；
6. 语言存储：坏值退回默认、读操作不创建文件、`data/settings.json` 存语言、时区
   与单轮最大输出（时区见 ADR-099，输出见 ADR-101）。

前端（`scripts/ui_check/dom-stub.test.mjs`）：
7. 每个 `data-i18n` 在 `web/i18n.js` 里都有对应 key（两个语言都要有）；
8. 切语言后：静态字、侧栏、输入框占位符、当前子页、消息流标签都变成英文；
9. `t()` 拿不到 key 时**不许静默返回空串**（要看得见）；
10. **`dom-stub` 与 `e2e-live` 都必须在 `app.js` 之前把 `i18n.js` 载进同一个 vm 上下文** ——
     `app.js` 里已经没有中文字面量了，少了这一步第一个渲染就 `ReferenceError: t is not defined`；
11. **自检 / 截图脚本不许靠界面文案找元素**（`shot.mjs` 原来用 `/格式化并初始化/` 找危险区按钮，
     界面一切英文它就永远找不到，而且报的是"等不到 Dream 页渲染完成"，像渲染坏了）：
     按结构定位（`.dream-format-open` / id / 类名），或者按**页面自己声明的 `<html lang>`**
     选期望措辞。`shot.mjs` 现在两种语言都能拍；
12. **文档截图每种语言各一套**：`chat-attachments[-en].png` / `chat-multimodal-ocr[-en].png`。
     脚本自己走 `/api/settings/language` 切两遍、**收尾切回原来的语言**，每轮断言
     "页面语言 == 刚设的语言" —— 否则会把另一套语言的图当成成果交上去。
     这两张（和中文那两张一样）**必须能重拍**：手动塞进去的英文图不可重拍，迟早腐烂（ADR-073）。

端到端（不在 unittest 里，但它才是"漏翻"的最终判据）：
11. `tmp_en_audit.py` 那种审计——把英文模式下**模型能看到的每一段框架文字**
    （提示词、末尾消息、摘要渲染、整理与压缩提示、**全部 16 个工具的描述与参数**、
    工具失败的 payload、每个 catalog 值）过一遍找汉字。单测只覆盖各自那一块，
    这条覆盖"整体"。

## 7. 定稿记录

* 用户拍板：范围 = Web 界面 + 模型侧全部（**CLI 输出保持中文**）；
  已有内容原样 + 提示词里说明"可能是中文写的"；**原地重渲染、不刷新**；
  `data/settings.json` + `HARNESS_LANGUAGE` + 默认中文。
* 语言选项标签本身也是界面文案（中文界面显示「中文 / English」，英文界面显示「Chinese / English」）。
