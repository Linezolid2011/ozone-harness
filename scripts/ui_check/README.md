# 界面自检（无浏览器）

这个目录里是**前端**的自动化检查。它不联网、不花钱、不需要装任何东西
（只用 Node 自带的 `node:vm`），也不需要浏览器。

## 为什么这么写

前端是零构建的原生 JS，而这一套自检**刻意不依赖浏览器**：同学的机器上不一定装了
Chrome，而这些检查要能离线、零依赖地跑。所以这里自己写了一个
**最小 DOM stub**（只实现 `web/app.js` 真正用到的那几个 API），在 `node:vm` 里
载入**真的** `web/app.js`，然后调用它的渲染函数、检查产出的 DOM。

（这台机器上其实**有** Chrome，headless 也能跑。这一轮就用它人工截过几张图
——正是这么发现"运行历史整片空白"那个赛跑 bug 的（见下面的"这一轮"）。
截图**不在仓库里**，也不进自检：它是证据，不是回归网。）

`web/app.js` 末尾有一行 `if (!globalThis.__HARNESS_NO_INIT__) init();` ——
这是**唯一**为测试留的接缝：设了这个变量就只载入函数库、不自动启动。
浏览器里没人设它，所以生产行为不变。

**它不是浏览器。** 它证明的是"代码路径与输出文本对不对"，证明不了
"页面看起来对不对"——布局、间距、深色主题、窄屏降级都**没有**被验证过。
这一点在报告里每次都如实写明。

## 怎么跑

> ⚠ **`e2e-live.mjs` 与 `shot.mjs` 会写盘，所以只能指向夹具目录。**
> 两个都会 `POST /api/settings/language`，那一步会**写数据目录里的
> `settings.json`**；`e2e-live` 的 vault 那几节还会真的建/改/删档案，
> `shot.mjs` 会往数据目录里种夹具会话、并往 `docs/screenshots/` 写图。
> 所以两个脚本在**任何写操作之前**都会先问服务端 `/api/config` 的 `data_dir`，
> **路径里没有 `tmp-` / `.tmp-` 这一段就直接拒绝运行**（退出码非 0，并打一句
> "该指向夹具、怎么起"的人话）。真需要对着别处跑才用 `E2E_ALLOW_REAL_DATA=1`
> —— 那时脚本会明说自己在明知故犯。
> 这是 ADR-050（写操作前先校验这块数据是不是我们该动的）＋ ADR-080（能预防就
> 不要靠提示）落到这两个脚本上的样子：文档里写十遍"别指向真实 `data/`"，
> 不如让它**跑不起来**。

```bat
:: 1) 造一份测试 vault（只写 .tmp-ui-check\data，不碰真实 data\）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\ui_check\seed-vault.ps1

:: 2) 起一个服务器指着它（另开一个窗口；--no-open 别弹浏览器）
::    **相对路径**就行：HARNESS_DATA_DIR 的相对形式按"项目根"解析，
::    所以谁 clone 到哪台机器/哪个目录都能照抄这两行，不用改盘符。
set HARNESS_DATA_DIR=.tmp-ui-check\data
python -m harness.cli --web --port 8791 --no-open

:: 3) 只跑 DOM stub（不需要服务器；夹具是手抄的响应字段）
node scripts\ui_check\dom-stub.test.mjs

:: 4) 端到端：把**真接口**的响应喂给真的 app.js
node scripts\ui_check\e2e-live.mjs http://127.0.0.1:8791

:: 4b) 可选：把「格式化并初始化 dream」的**真 200** 也跑一遍。
::     **它会真的清空这份夹具**，而且超过单文件写入上限（默认 12000 字符）的档案、
::     以及自定义 frontmatter 键（mood 之类）都写不回来 —— 只对一次性数据目录用，
::     跑完必须重新 seed-vault.ps1。所以它默认是关的。
set E2E_FORMAT_LIVE=1
node scripts\ui_check\e2e-live.mjs http://127.0.0.1:8791

:: 4c) 可选：把「真上传一张图」也跑一遍（`POST /api/attachments`）。
::     它会**真的往数据目录里写一个附件文件**，而且现在**没有删除接口** ——
::     只对一次性数据目录用。默认关着：后端的附件接口不在的话它会红。
::     关掉时这一节只验"入口三件套接在哪个元素上"（不发任何网络请求）。
set E2E_ATTACH_LIVE=1
node scripts\ui_check\e2e-live.mjs http://127.0.0.1:8791
```

`dom-stub.test.mjs` 出错时只打一行消息（`scenario` 会把异常收进结果单）。
想知道**哪一行**，加 `STUB_DEBUG=1`：

```bat
set STUB_DEBUG=1
node scripts\ui_check\dom-stub.test.mjs
```

跑完把 `.tmp-ui-check` 删掉即可（它已经在 `.gitignore` 里）。

## 重拍界面的截图（`shot.mjs`）

```bat
:: 前三张：Dream 页 / 危险区 / 格式化对话框 → 落在 outDir
node scripts\ui_check\shot.mjs http://127.0.0.1:8791 .tmp-ui-check\shots

:: 第 4/5 张（都在**对话页**，都不调模型）—— 每种语言各一套（ADR-085）：
::   docs\screenshots\chat-attachments.png      —— 附件缩略图那条
::   docs\screenshots\chat-multimodal-ocr.png   —— **默认折叠**的 OCR 气泡（契约 §13.7 第 3 句）
::   docs\screenshots\chat-attachments-en.png     ┐ 英文界面，
::   docs\screenshots\chat-multimodal-ocr-en.png  ┘ 同一次运行、同一份夹具
::
:: 同一个分支还会拍接口页的模型表格（ADR-092，一行一个模型）：
::   docs\screenshots\provider-models.png       —— 浅色
::   docs\screenshots\provider-models-dark.png  —— 深色（?theme=dark）
:: （第 3 个参数是**一次性夹具目录**，见下面那条警告）
node scripts\ui_check\shot.mjs http://127.0.0.1:8791 .tmp-ui-check\shots .tmp-ui-check\data

:: 也可以用 HARNESS_DATA_DIR 代替第 3 个参数

:: 只重拍提示词那五张（设置 → 提示词）：浅色 + 展开一组 + 编辑器 + 一条被改过的 + 深色，
:: 落在 `.tmp-shots\`，不写 docs\。⚠ 第 4/5 张要**真写盘**（种一条覆盖再复原），
:: 所以必须指向一次性夹具目录（下面前三行）。
set SHOT_PROMPTS_ONLY=1
node scripts\ui_check\shot.mjs http://127.0.0.1:8791 .tmp-ui-check\shots
:: 换落点：set SHOT_PROMPTS_DIR=<目录>
```

用 **headless Chrome + CDP** 真的打开页面、真的点开对话框，拍六张：
`01-dream-page`（整页）、`02-danger-zone`（滚到底的危险区）、`03-format-dialog`（确认框）
写进输出目录；第 4/5 张 **`chat-attachments.png` 与 `chat-multimodal-ocr.png` 直接写进
`docs/screenshots/`**（README 的「图片附件」与「多模态开关与 OCR」两节引的就是它们），
因为它们就是给文档用的那两张。

**第 6 张是「设置 → 提示词」页**（契约 `docs/13-prompts-page.md` ＋ 可编辑那份
`docs/14-editable-prompts.md` §8）：**五张** ——
**浅色 `prompts-page.png` ＋深色 `prompts-page-dark.png`**（这两张拍的都是**默认态**：
7 个分组全折着，也就是用户实际一进来看到的样子），
**`prompts-page-group-open.png`**（浅色，**展开第一个分组**、连同它里面第一条提示词的
原文 —— 让人看清展开之后长什么样），
**`prompts-page-editing.png`**（浅色，点开第一条的「编辑」：textarea 里是这一条当前
生效的正文 + 三句提示 + 保存 / 取消），
**`prompts-page-overridden.png`**（浅色，一条**真被改过**的样子：「已修改」徽标 +
各自的「复原」+ 一行 warn 色的后果提示 + 「当前生效 / 内置原文」两个折叠块）。
尺寸与 `chat-light.png` 同档（1440×900），落在
**项目根的 `.tmp-shots/`**（`SHOT_PROMPTS_DIR` 可改），**不写 `docs/`** —— 它现在是
"给人看一眼这一页长什么样"的证据，还不是哪一篇文章引用的插图。
浅色走 `#settings/prompts`；深色走 `?theme=dark#settings/prompts` 深链
（必须是**整页加载**才会执行 `initTheme()`，只改 hash 主题不会变；收尾会把
`localStorage` 里的主题清掉）。**前两张刻意不展开任何东西**：分组折叠（契约 §5 第 2 条）
要解决的就是"整页八千多像素"，图里必须看得出折起来之后有多短；只展开第一条提示词的
原文而不展开分组的话，`<pre>` 藏在折着的 `<details>` 里，图上什么也看不出来。
它**不调模型、不种会话**，所以不需要第 3 个参数（`SHOT_PROMPTS_ONLY=1` 就只拍这五张）；
但建议仍然指向一次性夹具目录（例如 `.tmp-ui-check-shot\data`），这样工具那一栏的
`生效 / 未注册 / 会话级` 三种徽标在图上都能看到。

**第 7 组是「设置 → 接口」页的那张模型表格**（ADR-092）：浅色
`provider-models.png` 与深色 `provider-models-dark.png`，两张都写进
`docs/screenshots/`（README 的「多供应商」一节引的就是浅色那张）。

拍之前脚本先断言**图里真的会有东西**：卡片里有两行、表头写着模型 ID / 上下文上限 /
显示名、「添加模型」在、而且老的两个输入框（`[data-f="models"]` 与
`[data-f="model_limits"]`）**已经没了** —— 不满足就不写文件（否则可能拍出"两处真相
并存"，而它看起来同样像拍成功了）。夹具里那份档案只有一个模型，看不出这张表的样子，
所以脚本**经真接口** `/api/providers/save` 把它改成两个模型（一个带上限、一个带显示名），
而不是往 JSON 里塞一份"代码还不支持的形状"。

本轮（ADR-092）基线：dom-stub **475 → 493**（+18：15 条盯这张表 + 3 条新的「守卫 10」；
0 失败；`e2e-live` 没动）。ADR-093（上下文接受 `128k` / `1M`）再 **+3 → 496**，
占位符变成 `200k`、`parseTokenLimit` 的纯函数表（含全部拒绝清单）、
以及"填 `128k` / `1M` 之后请求体里是 128000 / 1000000"。
收尾那一轮（ADR-095：前端 9 个 bug）再 **+31 → 527**，ADR-096（侧栏显示版本号）**+4 → 531**：会话切换竞态、工厂重置后清屏、
上传不覆盖 `sessionId`、SSE 逐帧隔离与缺省值、用量页容错、i18n 漏翻三处、
`#settings-meta` 串页、顶栏标题、两处 `innerHTML` 加固。**12 组变异验证**都实跑过。
**变异验证三条都实跑过**：① 删掉"重复 id 就拒绝"那段 → 「重复的模型 id」那条红
（并且它后面的 4 条同场景断言一起没跑，那一轮总数 486）；② 把"新行挂进表格"那一句
去掉 → 「加一行」那条红（失败信息就是 `应该多出一行`）；③ 从 `en` 里删掉一条文案
（`api.model_label_ph`）→ 守卫 10 报 3 条红，失败清单直接点名
`英文里缺这些 key：api.model_label_ph`。三次还原后 `web/app.js` / `web/i18n.js`
的 SHA256 都与基准**逐字节相同**，再跑一遍 493 / 0。

> 这一组踩过两个**脚本自己**的坑（不是界面问题），记在这里免得重犯：
> ① 卡片要挑 `.provider-card[data-id]` —— 页面上第一张 `.provider-card` 是
> 「新会话默认」那一块，它没有模型行；② 第一次导航去 `#settings/api` 时，如果
> 当前已经在 `#settings/prompts`，那只是**同文档的 hash 跳转**、页面不会重新加载，
> 而界面语言是**加载时**从服务端读的 —— 于是拍出一张"中文环境 + 英文表头"的图。
> 现在每次导航都带一个变化的 `?shot=N`，保证是整页加载。

⚠ **第 5 张（`prompts-page-overridden`）会真的写盘**：那条图上那个「已修改」标记、
那行 warn、以及页首"两门语言各改了几条"，全是按服务端回的 `overridden` /
`warnings` / `overrides` 画的 —— 用假 DOM 画一个标记出来不叫验证。所以它：

1. 先读 `/api/prompts` 确认夹具里**没有**覆盖（上一次跑崩了留下的会先报出来并复原掉，
   免得默认态那几张图凭空多出一个「已修改」标记）；
2. 经真接口 `POST /api/prompts/update` 种一条：把内置正文里**第一个占位符删掉** ——
   后端因此会给一句 warning，图上那行 warn 才是真的（只删不新增：新增一个内置里
   没有的占位符会被后端 400 拒掉）；
3. `Page.reload` 整页重载（覆盖是**服务端**的状态，只有重新拉一次 `/api/prompts`
   才会带上 `overridden` 与 `warnings`）；
4. 断言形态之后才写图：恰好一个分组开着、「已修改」＋「复原」都在视口里、
   那行 warn 非空且点到了占位符名、两个折叠块是「当前生效 / 内置原文」、
   页首写着 `中文已改 1 条 · 英文已改 0 条`；
5. `finally` 里**无论成没成都** `POST /api/prompts/revert`（带 id，只复原自己种的那条），
   并再读一次 `overrides` 核对"夹具没留下状态"。

第 4 张（编辑器）拍之前也有一套断言：**恰好一个** `textarea.pc-editor-area`、
里面的正文与 `/api/prompts` 给的那一条**逐字相同**、三句提示都在且都不为空、
「保存 / 取消」都在、它在视口里看得见（`rect.height > 80`）、编辑态里正文折叠块收起、
其余 21 条仍然带着「编辑」按钮。

**拍之前脚本会先把这一页验一遍，断言不过就不写文件**（照第 4/5 张那条规矩）：
`[data-prompt-id]` 恰好 22 个、`[data-tool-id]` 恰好 15 个、**7 个分组都是原生
`<details>` 且一个都不带 `open`**（少这条就可能拍出一张"其实没折"的图）、
第一条的原文处于**折叠态**（折叠着的时候 `<pre>` 必须不可见）、页面语言是中文、
这一页没被藏着、**没有对话框盖在上面**、以及这一路**零 `Runtime.exceptionThrown` /
零 `console.error`**。第三张拍之前另有一套断言：**恰好一个**分组开着、其余六组仍然
折着（不是手风琴）、展开的那一组里条目还在 DOM 里、第一条的原文真的可见。
最后两条是踩出来的：第 3 张拍完那个格式化确认框**不会自己关**，
第一版第 6 张就是"提示词页被对话框盖住一半"的图 —— 而它看起来像是拍成功了；
深色那一次还忘了调"展开"这一步，拍出一张全折叠的图，同样看着像成了。

**第 4/5 张每种语言各拍一套**（ADR-085）：脚本自己 `POST /api/settings/language` 切两遍
（中文 → 原来的文件名，英文 → `-en` 后缀），**收尾切回原来的语言**，
并且每轮都断言"页面声明的语言 == 刚设的语言"（没切成功就当场报错，不会把另一套语言的图当成果交上去）。
语言是**服务端**的设置，所以这一步需要起着的那个服务；它也会因此把语言值写进
（或更新）夹具目录里的 `settings.json` —— 一次性夹具目录无所谓，但**别指向你正在用的数据目录**。

**第 4/5 张不调用模型**：它们往数据目录里**种**两条会话
（`sessions/<sid>.jsonl` 里一条带 `attachments` 的 `user_message` + 一条明写"截图夹具"的
`assistant_message`，外加 `attachments/<sid>/<hash>.png` —— PNG 的 base64 内嵌在脚本里，
不依赖仓库根那份 `image.png`、更不依赖网络），然后刷新页面、**点侧栏那条会话**、
等缩略图加载完再截图。真调一次模型才能截图的话，这些图就不可重拍，迟早会腐烂。

* **OCR 那条**（`shot-ocr-fixture-0001`）：`user_message` 带
  `modality: "text"`，`attachments[0].ocr = {engine, seconds, chars, text}`
  （契约 §13.3），识别文字照抄上一版**真跑**出来的那段（换行与标点都保留）。
  界面上它会渲染成**默认折叠**的 `.ocr-block.collapsed`：缩略图 + 一行可点的标题
  （`▸ 多模态已关 · 只发送了下面的识别文本 · 118 字`）+ 一行截断的预览。
  脚本在截图前**会自己断言**这一形态（`collapsed`、标题末尾的字数 == `chars`、
  箭头是 `▸`、`.ocr-body` 还在），断言不过就抛错、不写文件 —— 免得把一张
  "其实没折起来"的图当成成果交上去。
  它还会往夹具会话里写一条 `session_tools{multimodal:false}`：少了它，截图里会出现
  "右上角多模态：开"配"气泡里多模态已关"这种自相矛盾，而且输入框附近那句
  "图片会随请求发给模型"也会冒出来（脚本同样断言了开关是"关"、那句提示是隐藏的）。
* **夹具接口档案**（`providers.json`，只在文件不存在时写）：一份 key 是假的
  `deepseek` 档案。没有它，截图右上角会写"（没有可用模型，去「设置 → 接口」添加）"、
  输入框下面挂一条琥珀色的"还没有可用的接口…" —— 文档截图看起来像坏了。
  key 是假的，真发一轮只会拿到 401，不会花钱；**已有文件时一个字节都不动**。
* 侧栏里按标题找会话用的是**精确匹配**（`.session-title` 的全文），不是 `includes`：
  后者会把一条更长的真实会话也算进来。找不到就抛错，把侧栏里实际有的标题打出来。

> ⚠ **第 3 个参数（或 `HARNESS_DATA_DIR`）只该指向一次性夹具目录**
> （例如 `.tmp-ui-check\data`）：跑完你的数据目录里会**多两条会话、两个附件文件**，
> 而且会出现在侧栏里；如果那个目录里原本没有 `providers.json`，还会多一份假 key 的档案。
> 脚本**拒绝**把它种进项目自己的 `data/`（那会污染真实对话列表），
> 但别的目录它管不着 —— 别指向你正在用的那份。
> 另外注意：**给出第 3 个参数会重写 `docs\screenshots/` 里那四张**
> （`chat-attachments.png` / `chat-multimodal-ocr.png` 与它们的 `-en` 版，都是同一次跑的产物）。
> 只想重拍其中一张时，记得先把其余几张备份出来、跑完再放回去。

> 🔎 **`SHOT_VARIANTS=1` 会多拍三张对照图**，落进 outDir（**不写 `docs/`**）：
> `variant-ocr-dark`（深色 1440×900）、`variant-ocr-narrow-dark`（深色 1120×820）、
> `variant-ocr-narrow-light`（浅色 1120×820）。DOM 自检证明不了"标题会不会挤成两行、
> 预览会不会被撑破、虚线框在深色底上还看不看得出来"，这三张就是给眼睛看的。
> 深色走的是 `?theme=dark` 深链（`app.js` 里本来就为截图留了它），收尾会把
> `localStorage` 里的主题清掉，免得污染 `outDir/profile` 里那个 Chromium 配置。

> ℹ **`docs\screenshots\chat-multimodal-ocr.png` 曾经是只读的**（Windows 的
> `ReadOnly` 属性），直接重拍会 `EPERM: operation not permitted` —— 而且报错发生在
> 前三张（写在 `outDir`）与 `chat-attachments.png` 都写完之后，看起来像脚本坏了。
> 重拍前先清掉：
> `powershell -Command "Set-ItemProperty docs\screenshots\chat-multimodal-ocr.png IsReadOnly $false"`

它只用 Node 内置能力（全局 `WebSocket` + `fetch`），但**需要机器上装了 Chrome**。
查找顺序：`CHROME_PATH` 环境变量 → `%ProgramFiles%` / `%ProgramFiles(x86)%` /
`%LOCALAPPDATA%` 下的 `Google\Chrome\Application\chrome.exe` → PATH 上的
`chrome` / `google-chrome` / `chromium`。**刻意不写死盘符** —— 写死之后系统装在 D 盘
或换台机器就坏，而且仓库里那条可移植性守卫也会拦（它真的拦过我这一版）。

**两条硬规矩**：

1. **只按 PID 杀自己起的那一个 Chrome**（脚本里是 `child.kill()`，必要时补一刀
   `taskkill /PID <pid> /T /F` —— **仍然是按 PID**）。有一次收尾时按**进程名**
   `Stop-Process chrome` 杀，把**用户自己正在用的浏览器**一起杀了 ——
   这种"顺手清理"造成的损失比不清理大得多；
2. 用**单独的 `--user-data-dir`**（脚本建在输出目录下的 `profile/`，**绝对路径**），
   不碰用户自己的浏览器配置与登录态。

> ⚠ **"杀了"的唯一判据是端口已释放，不是 kill 没报错**（ADR-079：别用代理指标
> 判断状态）。这条是别人踩出来、我这边复核后确认的：`Start-Process -PassThru`
> 给的是**启动器**的 PID，`Stop-Process` 那个 PID 之后，**子进程还占着端口** ——
> 命令没报错、进程看着也没了，可服务还活着，下一次自检会连到一个**你不知道它存在**
> 的旧实例上（症状是"夹具明明是新的，接口却回旧数据 / 语言自己会变"）。
> 所以服务器（`python -m harness.cli --web`）与 Chrome 都一样，杀完**复核一次**：
> ```bat
> :: Windows：按端口看还有谁在听（没有输出 = 真释放了）
> netstat -ano | findstr :8791
> :: 或者
> powershell -Command "Test-NetConnection 127.0.0.1 -Port 8791 -InformationLevel Quiet"
> ```
> Chrome 那边对应的是 `http://127.0.0.1:<调试端口>/json/list` 连不上。
> 端口还活着就按**那个还活着的 PID**（`netstat` 最后一列）再杀一次。
> 顺带一条：**一次自检只连一台服务**。两个自检（比如 `e2e-live.mjs` 与 `shot.mjs`）
> 指向同一台服务器时会互相抢运行期设置 —— 语言是**服务端**的，一边切 zh、另一边切 en，
> 两边的断言都会看到"我设的值怎么不是这个"。各起各的端口。

### 两个"起没起来"的坑（都真的踩过）

* **`spawn` 找不到可执行文件时抛的是异步 `'error'` 事件，`try/catch` 接不住。**
  没有监听器就是一个未处理的 error → 整个进程当场崩，**连"换下一个候选"都走不到**，
  `findChrome()` 那个"到哪都对"的承诺也就兑现不了（Chrome 只装在 `%LOCALAPPDATA%`
  的每用户安装机器上必然踩到）。现在每个候选都挂 `error` 监听并收 `stderr`，
  失败原因留到最后一起报出来。
* **不许用 `exitCode` 判断"这个候选起没起来"**：Windows 上 Chrome 的**启动器进程会先退出**，
  真正的浏览器进程继续跑。早先那句 `await sleep(400); if (chrome.exitCode === null) break;`
  会把一个**正常启动**的 Chrome 当成"起来了又死掉"扔掉，然后去试下一个候选。
  现在的判据只有一个：**CDP 端口活过来**（轮询 `/json/list` 拿到 page 目标），
  超时才换下一个，换之前按 PID 杀掉自己起的那个。
  收尾也反过来：**先发 CDP 的 `Browser.close`**（明确关掉自己这一个实例），
  再兜底 `kill()` —— 启动器先退出的情况下，只 kill 那个 PID 可能关不掉真正的浏览器进程。
* 顺带两条同源的：`/json/list` 里那个 page 目标**一开始是 `about:blank`**
  （命令行给的地址还没加载），`document.readyState === 'complete'` 在它上面立刻为真 ——
  所以现在等的是"应用外壳出现"，而且**还要等 `init()` 把导航接上**
  （`item.onclick` 是最后几步才赋的，早一点点侧栏那个「Dream」什么都不会发生，
  截出来是一张对话页 —— 真的截到过）。

## 几条经验（踩过才写下来的）

* **这台机器上有 Chrome，所以"视觉没法验证"不成立**（前面十几轮一直这么写着，
  其实早该用 headless 拍一张）。能拍就拍 —— 这一轮的 Dream 页就是这样发现
  "运行历史整片空白"的（`/api/vault` 与 `/api/dreams` 的赛跑，见下）。
* **截图会腐烂，所以它必须可再生**：`docs/screenshots/dream.png` 曾经还是
  "预演 / 一键回滚 / 会改写记忆库"那一版 —— 三个功能早删了，图还留在文档里
  （而且当时 README 没引用它，所以谁都没发现）。现在的做法是**脚本能随时重拍**，
  引用也放进 README。
* **断言里不要写死夹具的数字**。`e2e-live.mjs` 里"截断提示"那条一开始写死了
  `/281999/`（当天那份夹具的字符数），换一份同内容的文件就假红，而界面其实是对的。
  现在它拿**真响应**里的 `chars` / `total_chars` 来对，夹具没超上限时明确跳过。
* **stub 的 `innerHTML` 是手写的解析器**，不是真 HTML 解析器。所以
  "正文里的 `<script>` 只作为文本渲染"这条断言，验的是 app.js 有没有用
  `textContent` 建节点，而不是浏览器的真实行为 —— 但这个区别恰好是我们关心的那条。
* **stub 的 `getElementById` 是"边用边造"的**（它没有真 DOM 的 id 索引，只能
  在你问某个 id 时临时造一个空 `div` 顶上）。这有两个后果，都很容易让人写出一条
  永远为真的假断言：
  1. 查一个**没画出来**的 id 会拿到一个空 div，而不是 `null` —— 所以断言要
     "从文档里找"（本文件里的 `field()` 就是这么写的），别用 `byId.get()`；
  2. app.js 里凡是"往一个按 id 取出来的容器里画东西"的地方，都要保证
     **页面上那个节点与 `getElementById` 指到的是同一个**（见 `web/app.js` 的
     `reuseOrCreate()` 与 `renderVaultEditor()`：编辑器里的输入框一律从**本次的
     容器子树**里取，取到就复用，而不是新建一个）。
  第 2 条不是"为了自检而写" —— 真的新建一个的话，浏览器里就会出现
  "页面上那个输入框没人监听输入"，只是肉眼看不出来。自检抓到的正是这类错位。
* 覆盖到的：目录树（含嵌套与计数）、开合与选中状态的保持、点文件发的 URL、
  查看器的属性区/正文/邻域、`[[双链]]` 命中与未命中、README 索引标注、
  404/400 文案、截断与警告、**正文里的 `<script>` / `<img onerror>` 不被执行**；
  以及新建 / 编辑 / 删除：动作条（README 不给删除按钮）、编辑态预填、
  保存时发出去的 URL 与请求体（含 `expect_hash`）、409 被改过时输入框不丢字、
  409 撞名的"打开它"、删除确认里列出反链、成功后的重刷与 `dangling` 展示、
  编辑态里的 `<script>` 只作为文本。
* 原生 vault（ADR-104）：`![[raw/...]]` 渲染成 `<img>`（src 走
  `/api/vault/raw`）、`[[sections/x|别名]]` 显示别名并点向真实路径、
  嵌套 frontmatter（`relation` 列表套映射 / `date` 嵌套映射）不显示成
  `[object Object]`、生成物没有编辑/删除按钮并说明原因。
* 后来这一轮加的（三条，见下面的"这一轮"）：
  * **加粗里的双链**：`**[[X]]**` 必须渲染成 `<strong>` 里的可点链接。
    以前 `bold` 是按纯文本塞进 `<strong>` 的，于是同一段里 `[[X]]` 是蓝的、
    `**[[X]]**` 却原样显示方括号 —— 看起来"有时行有时不行"。
    夹具直接用用户截图里那一行
    （`科研：主攻 **[[AI4Science]]**，已投稿一篇论文到 **ICLR 2027**，审稿中。`：
    一个加粗双链 + 一个普通加粗），比只测裸的 `**[[X]]**` 更贴近现实。
    断言里还有一条**最能抓回归**的：代码之外的渲染文字里不该再出现 `[[` 与 `]]`
    （行内码与代码块里的**必须**还是字面量，`textOutsideCode()` 就是为这条写的）。
  * **中文字段标签**：界面上是「标题/类型/关系/状态/标签/别名」，
    英文键名退到输入框的 `title` 提示里。同时**必须**验"契约没变"——
    真存一次，断言请求体的键名还是 `title/kind/relation/status/tags/aliases`，
    而且值没有串到别的键上（改文案最容易犯的错）。
  * **插入链接**：「插入链接」按钮 → 列出 vault 里现有的档案（`entities/`、
    `sections/`，含更深的子目录）→ 点一项把 `[[title]]` 插到**光标处**
    （没有选区信息就追加到末尾）→ 焦点与光标交回 textarea。
    夹具里故意放了一份**标题 ≠ 文件名**的档案（`entities/xiaozhang.md` / 标题「小张」），
    插进去的必须是 `[[小张]]` 而不是 `[[xiaozhang]]` —— **不带目录、不带 `.md`**：
    服务端是精确匹配（标题/别名/文件名，不折大小写、不剥前缀），
    宽容写法一律该是"还没写"。另外还有一个手打名字的输入框
    （指向还不存在的档案 = 正常用法）。
    `e2e-live.mjs` 里还真的建了一份**标题 ≠ 文件名**的临时档案，
    再用它的**标题**从别处链过去，验服务端真能解析出来 ——
    "插进去的字符串对不对"与"这条链接真的通到文件"是两回事。
  * **「还没写」→ 建它**：`vault-link missing` 那个 span **一个字节都没改**
    （仍然是 span、`onclick` 仍然是 null、文字就是那个名字、title 仍是
    "这个档案还没写"——既有断言盯的就是"界面上没假装能读一份不存在的档案"），
    但它被包进了一个**透明的** `<button class="vault-link-create">` 里：
    点那段虚线文字就命中按钮 → 问一句「《X》这份档案还没写，要现在建一份吗？」
    → 同意就进新建态，名字与标题都预填成 X，路径实时算出来。
    自检里断言的是"虚线文字确实在那个按钮**里面**"（浏览器里点文字才会命中按钮），
    真正"点文字"这件事本身 stub 模拟不了，只能靠这层父子关系。
* `e2e-live.mjs` 最后一段会**真的往 vault 里建一份临时档案**
  （`tmp-ui-check-新建甲`，正文里带 `**[[小林]]**` 与 `` `[[小林]]` ``，
  用来在**真接口回来的数据**上再验一遍加粗双链），在它上面走一遍
  新建 → 编辑（含「插入链接」）→ 409 冲突 → 覆盖 → 删除，
  最后把临时档案与被它改过的小林都恢复原样。它开头会先清掉可能残留的同名档案，
  所以上一次自检中途挂掉也不会让下一次假红；但它**不该**跑在真实 data/ 上。
* 这一轮加的（预演取消 + 「格式化并初始化 dream」，ADR-072）：
  * **预演没有入口了**：`index.html` 里那个「预演一次」按钮与文案都删了；
    `app.js` 里 `runDream()` 不再接 `dry_run`，也不再有 `dry` 分支。
    断言分三层：① Dream 页渲染出来的 DOM 里**没有**任何名字带「预演」的按钮；
    ② `index.html` / `app.js` **源码**里不再有「预演一次」（按钮藏在 index.html，
    DOM stub 不加载它，只能这样看文件 —— 这一条是静态检查，说清楚）；
    ③ 点「整理一次」发出去的请求体里**没有 `dry_run` 键**
    （`deepEqual(Object.keys(payload).sort(), ['effort','limit','model','provider'])`）。
    第 ③ 条是这轮最重要的一条：后端见到 `dry_run` 会直接 400（ADR-072），
    而那正是"旧页面以为在预演、其实在写档案"那个坑的反面 —— 前端少发一个字段，
    这件事只能靠请求体断言盯住。
  * **历史里的旧预演记录照旧能显示**：`mode: "dry-run"` 的运行记录仍然画得出来
    （chip 上是中性的「预演（旧功能）」，详情里说"当时没有改动任何档案"），
    只是页面上没有任何"再发起一次"的入口。这条和上面那条是**互补**的：
    一个删入口，一个保历史 —— 只做前者会把老记录显示成"已应用"（那是假话）。
  * **格式化并初始化的双重确认**：对话框里先列清要失去什么（档案 / 运行记录 /
    整理进度，数字当场从 `/api/vault`、`/api/dreams` 重新拉）与**不会被碰**的东西
    （对话历史 / 记忆条目 / 接口配置与 key，来自 `/api/reset`）；
    确认词必须打对，「执行格式化」才从 disabled 变可用。请求体是
    `{confirm: "<词>"}`（`deepEqual(Object.keys(payload), ['confirm'])`）。
    执行完之后 before → after 留在**页面上**（不是一闪而过的 toast），
    `leftovers` 非空时警告"请手动删"。
  * **确认词不硬编码**：`app.js` 里那个词只写一处（默认值），后端 `400` 里回的
    `confirm_word` 一旦不同，提示与门禁**就地改成后端那个词**。
    自检里用一份"词不一样"的 400 验这条（打旧词会被重新禁用、打新词才发得出去），
    `e2e-live.mjs` 里再用**真的** 400 验一次"界面用的词 == 后端要的词"
    （硬编码真正会坏的形态就是这两边悄悄走样）。
  * **失败不关对话框**：400 / 409 的后端原话显示在对话框里、可以改完再试
    （`openDialog` 为此多了一个 `onConfirmError`；恢复出厂设置那条仍走原来的行为）。
  * `e2e-live.mjs` 里**真 400**（确认词不对）会验"什么都没做"（档案数一个都没少）；
    **409（整理正在运行）造不出来** —— 要真的跑一次整理才会占住那把锁，而那是要花钱的，
    所以这一条用的是**合成**响应，验的是前端分支（原话照显示、对话框不关），
    报告里要如实写明这一点。
  * **真 200 默认不跑**（`E2E_FORMAT_LIVE=1` 才跑）：它会真的清空夹具，而接口
    **写不回**自定义 frontmatter 键（只有 title/kind/relation/status/tags/aliases
    六个键）与超过单文件写入上限的档案（seed 那份"长档案"就是这种）。
    开着跑时，自检会把**能**写回去的都写回去、把写不回去的如实报出来
    （不假装成功），并提示重新 seed。
  * **顺手修掉一个赛跑 bug**（不是这一轮要求的，是截图里撞见的）：`/api/vault` 与
    `/api/dreams` 是并行拉的，而运行历史的容器是 vault 那次渲染用 `innerHTML`

## 这一轮补的断言（以及一个真 bug 的旁证）

* **整理进度里"待整理会话"那一行**（`· <id>…`）以前是 `web/app.js` 里拼出来的
  硬编码中文（`` `· ${item.session_id}「${item.title || '(无标题)'}」` ``）——
  英文界面下它照样冒出「」和"(无标题)"。现在整行走 i18n
  （`dream.record_line` / `dream.untitled`），并补了两条断言：中文下是
  `· s1「ProjectA」`，英文下是 `· s1 "ProjectA"` 且**这一行一个汉字都没有**。
  同一次运行的进度里还有后端给的 `tool_result` 文案（"已写入 …"），那类文字前端
  一个字都不翻（`i18n.js` 文件头的约定），所以"没有汉字"只对**这一行**成立 ——
  断言是按行找的（`recordLine()`），不是对整段进度断言。
  夹具里 `pending.detail` 因此**必须留一条**（以前是空的 `[]`）：空着的话这一行
  根本不会被渲染，新断言就成了永远为真的空话。
* **变异验证**：把那两行改回硬编码中文 → 英文那条断言立刻红
  （`这一行不该有汉字：· s1「ProjectA」 4 条新记录…`）；恢复后
  **479 断言 0 失败**（这一轮 476 → 479，加 3 条）。`e2e-live.mjs` 这一轮也实跑了：
  **90 断言 0 失败**（对着 `.tmp-ui-check\data` 起的一次性夹具，基线不变）。
* **`themeLabel()` 是死代码**（真正生效的是 `renderThemePane` 里内联的三条
  `t("theme.*")`）。它之所以还"活着"，只是因为本文档上面那份 `EXPORTS` 把它导了出去
  —— 所以删函数时**必须同时从 `EXPORTS` 里删掉**，否则整个自检会在
  `vm.runInContext` 那一步直接 `ReferenceError`（不是某条断言红，是根本跑不起来）。
* **前端没有"两门语言的键集必须一致"的守卫**（后端有 `tests/test_i18n.py` 那种）。
  这一轮新增的两个 key 是靠人工同时写 zh/en 保证的；`t()` 缺 key 只会
  `console.warn` + 返回 key 本身，所以"只写一门"不会红 —— 要不要补守卫另说。
